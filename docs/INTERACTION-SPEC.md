# 三页交互改进规格书

> 范围：下载页 / 游戏站页 / 设置页，每页只做最痛的一项。
> 前置：测试债已还（`npm run regression` 一键回归全绿）。
> 原则：只改交互闭环缺口，不动视觉系统、不引入新依赖、不加 AI 味。

---

## 1. 下载页 · 完成汇总条（Task 1）

### 1.1 痛点

任务完成时只有单个任务行换状态图标。一批任务（尤其来自游戏站的批量捕获）混跑时，
用户看到列表整体绿了，以为全好，实际有失败项藏在列表下方；失败原因收在行内小图标里，
不醒目。**「批的结局」没有一次说清。**

### 1.2 方案

在下载页工具栏与任务列表之间，加一条**批状态汇总条**（仅在有「本次会话内刚结束」的
任务时出现，不常驻占空间）。

- 位置：`.dl-toolbar` 下方、`.dl-list` 上方，独立一行。
- 内容：`3 个完成 · 1 个失败 · 1 个暂停`（数字实时来自现有 `counts` 计算属性）。
- 有失败项时：整条底色用 `--hh-color-error` 的浅色派生（不刺眼），文字「失败」用
  实色 error；无失败项时：用 `--hh-color-success` 派生浅色底。
- 失败计数可点击：点击后 `downloads.taskFilter = 'error'` 切到失败筛选，
  失败行全部可见；再点一次切回 `all`。
- 完成计数可点击：切到 `done` 筛选。
- 与现有「清除已完成」「重试失败」两个工具栏按钮呼应：汇总条是提示，按钮是动作。

### 1.3 显示条件（关键，避免噪音）

汇总条只在**有任务刚结束**时出现，且满足下面任一：

- 本次进入下载页后，有任务从非终态（downloading/paused）进入终态（done/error/cancelled）
  —— 即「正在发生的事有结果了」；
- 或当前 `rows` 里存在 error/cancelled 任务（历史失败还在，常驻提醒，直到被清除/重试）。

实现：`downloads.store` 加一个轻量状态 `batchEvent: { done: number; error: number }`，
任务状态变更的订阅处累加；汇总条 `v-if="batchEvent.error > 0 || batchEvent.done > 0"`。
「清除已完成」「重试失败」「移除」后对应计数归零/重算；离开下载页不清零（本次会话内有效）。

### 1.4 不做

- 不做完成 toast（已完成：单任务 done 有通知/引导）。
- 不做批量完成动画（噪音 > 价值）。

## 2. 游戏站页 · 搜索空态给出口（Task 2）

### 2.1 痛点

三站搜索后若某站无结果，只显示灰色「无结果」文案——死胡同。真实场景：站内搜索被反爬、
或资源站收录不全。用户需要「这个站搜不到，去别处找」的出口，而不是盯着空态发呆。

### 2.2 方案

搜索结果组的空态（`.g-empty`）增加**上下文出口按钮**：

- 站点搜索无结果（`outcome.ok && results.length === 0`）：
  - 主按钮「用浏览器打开 {站名}」→ `window.hh.webviewOpenExternal(site.home)`（通道已有）。
  - 副按钮「换关键词」→ 聚焦搜索框（`searchKeyword.value = ''` + 输入框 `focus()`）。
- 站点搜索失败（`!outcome.ok`，被反爬/超时）：
  - 主按钮「重试」→ 现有 `retrySite(g)`。
  - 副按钮「用浏览器打开 {站名}」→ 同上（失败时也给出人工兜底）。
- 空态文案从「无结果」升级为带引导：「{站名} 没搜到，换个词或去浏览器里翻翻」。

### 2.3 不做

- 不做跨站聚合重试（多站同时失败的批量重试已由三列各自重试覆盖）。
- 不做空态插画/装饰（克制，纯文字+按钮）。

## 3. 设置页 · 未保存角标（Task 3）

### 3.1 痛点

设置页是「改完必须点保存」的模型（部分项如主题即时生效，代理/目录/并发等要等点保存），
但界面从不提醒「你改的还没保存」。用户改完代理直接关弹窗，以为生效了，实际白改。
这是文件头注释自己承认的高发事故（「用户会发现『勾了没保存』」）。

### 3.2 方案

- 弹窗打开时保存一份 `props.settings` 快照 `original`；
  `dirty = computed(() => JSON.stringify(form) !== JSON.stringify(original))`
  （`form` 是 `reactive({...props.settings})` 副本，直接字段对比即可，
  不比对 `settings` 对象本身——防 props 重传误报）。
- `dirty` 为真时：
  - 保存按钮从「保存」变为「保存 ●」——加一个实心圆点角标（`--hh-color-accent`），
    且 `aria-label` 带「有未保存的更改」；
  - 弹窗标题旁加一行小字「有未保存的更改」（页签下方或标题右侧，用 `--hh-color-text-tertiary`）。
- 保存成功后 `original = { ...form }`，角标消失。
- 不做关窗拦截确认（`@cancel` 时如果 dirty 弹 `Modal.confirm`）——那是第二档，
  本次先做「看得见」，关窗确认留给下一轮。

### 3.3 注意

- 主题/外观页签的即时生效项（`dark`/`theme_mode`/`theme_preset`）也在 `form` 里，
  它们一改就生效，但也算进 `dirty`——点保存会把整份设置落盘，语义没错（保存全部当前值）。
  若导致角标常亮（改了外观但不想动其它项），可接受：点一下保存即消。
- `JSON.stringify` 对比依赖字段顺序稳定（`form` 与 `original` 同源构造，顺序一致）。

## 4. 验收

| 项 | 验收方式 |
|---|---|
| 1 汇总条 | 回归脚本：seed 一批含 error 的任务 → 下载页出现汇总条、数字正确、点失败计数切到 error 筛选 |
| 2 空态出口 | 回归脚本：mock 搜索返回空/失败 → 空态含「打开浏览器」按钮、点击调 webviewOpenExternal |
| 3 未保存角标 | 回归脚本：打开设置 → 改代理值 → 保存按钮出现角标 → 点保存 → 角标消失 |
| 全量 | `npm run regression` 六件套全绿 |

## 5. 不做清单（防止范围蔓延）

- 不动三页的视觉系统/布局。
- 不引入新依赖。
- 不新增 IPC 通道（全复用现有桥）。
- 设置页关窗拦截确认留到下一轮。
